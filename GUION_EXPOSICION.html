Guion 2 · Johan — Arquitectura, cookies/sesión, hash y base de datos

Duración: 8 min · Rama: rutabol-requerimientos · Objetivo: explicar la capa técnica y los RNF.

0:00 – 0:30

Arquitectura

Tarjeta y diagrama de REQUERIMIENTOS.md §2.
Decir
“Soy Johan. Esta es la arquitectura: Next.js en el navegador, API NestJS bajo /api y PostgreSQL con volumen persistente. Entre el navegador y la API hay una cookie de sesión; dentro de la API hay dos capas globales: RolesGuard y AuditoriaInterceptor.”
0:30 – 2:20

Cookies y sesión

Terminal:
curl.exe --ssl-no-revoke -i -X POST https://www.rutabol.test/api/auth/login -H "Content-Type: application/json" -d '{"username":"pasajero1","password":"RutabolDemo123"}' | Select-String 'HTTP/|Set-Cookie'
Después, con jar de cookies:
curl.exe --ssl-no-revoke -c cookies.txt -X POST https://www.rutabol.test/api/auth/login -H "Content-Type: application/json" -d '{"username":"pasajero1","password":"RutabolDemo123"}'
curl.exe --ssl-no-revoke -b cookies.txt https://www.rutabol.test/api/auth/me
Remove-Item cookies.txt
Decir
“Fíjense en el Set-Cookie: rutabol.sid, HttpOnly, Secure y SameSite=Lax. HttpOnly evita que JavaScript lea la cookie; Secure la obliga a viajar por HTTPS; SameSite=Lax reduce el riesgo de envío cross-site. Es host-only, no un dominio compartido. La sesión no vive en localStorage: se guarda en PostgreSQL con connect-pg-simple, en su propia tabla. Con /api/auth/me comprobamos la identidad, y /api/auth/logout la destruye. Los endpoints públicos no piden sesión; los de rol sí pasan por RolesGuard. Eso es RNF-01 y RNF-02.”
2:20 – 3:40

Hash de contraseñas

Terminal:
docker compose exec -T postgres psql -U micros -d micros_scz -c "SELECT username, left(password_hash, 7) AS prefijo, length(password_hash) AS longitud FROM usuarios ORDER BY username;"
Decir
“En la base no se guarda la contraseña: se guarda un hash bcrypt con factor de costo 12. El prefijo $2b$12$ y los 60 caracteres lo confirman. En el login se compara con bcrypt, nunca se desencripta. Tampoco aparece en auditoría: el interceptor sanea contraseñas, tokens y fotos. Y en pagos solo viaja un token simulado, así que no hay datos de tarjeta: RNF-15.”
3:40 – 6:10

Base de datos

Terminal:
docker compose exec -T postgres psql -U micros -d micros_scz -c "\dt"
docker compose exec -T postgres psql -U micros -d micros_scz -c "\d micros"
docker compose exec -T postgres psql -U micros -d micros_scz -c "\d pagos"
Después, database/01_init.sql líneas 12–18 y 83–96 en el editor.
Decir
“Son 14 tablas más la tabla de sesiones. La integridad no depende del frontend: UNIQUE en placa, interno, referencia de pago y código de estudiante; claves foráneas entre viajes, pagos, abordajes y trasbordos; CHECK de capacidad entre 18 y 25, de latitudes entre -90 y 90, y de estados válidos. Hay índices, incluidos índices parciales para la tarifa activa y el viaje en curso de un micro. Los datos de demostración se crean solos al inicializar. Eso es RNF-09, y es lo que evita estados imposibles aunque alguien llame a la API directo.”
